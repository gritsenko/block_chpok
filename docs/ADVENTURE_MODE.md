# Режим «Приключение»

Прохождение по уровням с целями, лимитом ходов, препятствиями, жизнями и бустерами.
Классика (бесконечная партия на рекорд) осталась без изменений — режим выбирается
на стартовом экране.

---

## 1. Файлы и зоны ответственности

| Файл | Отвечает за | Когда править |
|---|---|---|
| `src/levels.js` | **Данные уровней**: главы, layout, цели, лимит ходов, подсказки | Добавление/балансировка уровней |
| `src/adventure.js` | Мета-логика: разбор layout, прогресс целей, звёзды, жизни, бустеры, весь UI режима | Новые механики/цели |
| `src/game.js` | Ядро: доска, драг, линии, слой препятствий | Правила игры |
| `src/leaderboards.js` | Фасад лидербордов (Yandex сейчас, jam-sdk позже) + модалка рейтинга | Смена провайдера |

Порядок подключения в `index.html` важен: `levels.js` → `leaderboards.js` →
`adventure.js` → `game.js`. Ядро на старте читает `window.Adventure`, чтобы решить,
показывать ли кнопку режима: если `levels.js` не загрузился, кнопка «Приключение»
просто не появится, и игра работает как раньше.

### Контракт ядра ↔ приключения

Ядро не знает ни про цели, ни про жизни, ни про прогресс.

```
adventure.js  --> window.GameCore.startGame({ mode, level })   запуск уровня
                  GameCore.setInputLocked / setHammerArmed     ввод и бустеры
                  GameCore.reshuffleTray / addBombTurns        команды бустеров
                  GameCore.maybeShowInterstitial(ms, next)     общий лимит рекламы
game.js       --> window.Adventure.onPlacement(event)          один вызов на ход
                  Adventure.onHammerUsed / onDeadlock / onScoreChanged
```

`onPlacement` вызывается **один раз за ход и уже после разбора линий**, поэтому
`adventure.js` всегда видит финальное состояние доски. `event` содержит
`{ blocksPlaced, lines, combo, collected, score, explodedBombs }`, где `collected` —
итог хода: `{ blocks, crates, rocks, ice, gems, bombs, colors }`.

## 2. Как добавить уровень

Дописать объект в `window.ADVENTURE_LEVELS` в `src/levels.js`. Больше ничего менять
не нужно: карта, HUD, звёзды и лидерборд подхватывают его автоматически.

```js
{
    id: 41,                                   // следующий по порядку, без пропусков
    name: { ru: 'Ночная полка', en: 'Night Shelf' },
    moves: 16,                                // жёсткий лимит размещений
    goals: { crates: 'all', lines: 5 },       // выполнить нужно ВСЕ цели
    layout: [                                 // необязательно; ровно 8 строк по 8 символов
        '........',
        '..cc cc.'.replace(' ', '.'),         // (в реальном файле — просто 8 символов)
        '........',
        '........',
        '........',
        '........',
        '........',
        '........'
    ],
    hint: { ru: 'Сначала верхний ряд.', en: 'Clear the top row first.' },
    shapes: 'small'                           // необязательно: 'small' | 'big' | 'lines'
}
```

Главы задаются отдельно в `window.ADVENTURE_CHAPTERS` (`{ id, from, to, name, bg }`) —
если новый уровень выходит за диапазон последней главы, расширьте её `to` или
добавьте главу. `bg` — фон главы на карте (см. [Фоны глав](#8-фоны-глав-на-карте)),
поле необязательное: без него карта остаётся на тёмной подложке.

### Легенда layout

| Символ | Значение |
|---|---|
| `.` | пустая клетка |
| `#` | **дыра**: ставить нельзя, клетка ИСКЛЮЧЕНА из сборки линии (ряд с двумя дырами закрывается шестью клетками) |
| `*` | стартовый блок случайного цвета |
| `r g b y p o` | стартовый блок фиксированного цвета (red/green/blue/yellow/purple/orange) |
| `s` `S` `T` | **камень** на 1/2/3 удара: ставить нельзя, для линии считается ЗАПОЛНЕННЫМ, скалывается очисткой линии |
| `c` `C` | **ящик** на 1/2 удара: механика камня + цель `crates` |
| `i` `I` | **лёд** на 1/2 удара: клетка пустая и доступна для фигур, тает при очистке линии над ней + цель `ice` |
| `d` | **самоцвет**: цветной блок с камнем внутри, собирается при очистке + цель `gems` |
| `1`–`9` | **бомба** с обратным отсчётом: занимает клетку, считается заполненной, счётчик падает после каждого хода, очистка линии обезвреживает. **0 = мгновенный проигрыш** |

Следствия, которые надо держать в голове при дизайне:

* камни/ящики/бомбы **упрощают** свою линию (её нужно дозаполнить, а не заполнить)
  и одновременно **сокращают** место под фигуры;
* лёд линию не упрощает — по нему надо сначала поставить фигуру;
* дыры укорачивают линии, это самый мягкий регулятор сложности;
* линия сбрасывается только если в ней есть хотя бы один цветной блок — ряд из
  одних камней сам себя не очищает;
* стартовая уже собранная линия = бесплатный сброс на первом ходу, так делать нельзя.

### Цели

| Ключ | Значение | Смысл |
|---|---|---|
| `score` | число | набрать очков |
| `lines` | число | собрать линий (2 за один ход = 2) |
| `blocks` | число | снести блоков |
| `crates` | число или `'all'` | разбить ящиков |
| `ice` | число или `'all'` | растопить льда |
| `gems` | число или `'all'` | собрать самоцветов |
| `bombs` | `'all'` | обезвредить все бомбы |
| `combo` | число | серия из N подряд ходов с очисткой |
| `placements` | число | поставить N фигур («выживание») |
| `colorClear` | `{ color, count }` | снести N блоков одного цвета |

`'all'` считается по layout на старте уровня. Если соответствующих символов в layout
нет, цель отбрасывается с предупреждением в консоли.

### Балансировка

Ориентиры на один ход у уверенного игрока: **80–110 очков** и **~0.35 линии**.

| Сложность | Очки/ход | Линии | Цели-препятствия |
|---|---|---|---|
| Лёгкая | 55–70 | `moves / 4` | 1 на 3 хода |
| Средняя | 75–90 | `moves / 3.2` | 1 на 2.5 хода |
| Сложная | 95–115 | `moves / 2.8` | 1 на 2 хода |

Несколько целей на уровне **делят** этот бюджет, а не складывают его.

Формула очков (из `game.js`): за ход `10 * блоков * (линий + 1)`, плюс при очистке
`линий * 100 + (комбо - 1) * 50`.

### Проверка уровней

На `localhost` при загрузке автоматически запускается валидатор
(`window.Adventure.validateLevels()`), который пишет в консоль:

* дубли и пропуски `id`, некорректный `moves`;
* layout не 8×8 и неизвестные символы;
* цели, схлопнувшиеся в ноль;
* уже собранные на старте линии;
* доску, где свободно меньше 45% клеток (риск мгновенного тупика).

Проверить можно и вручную из консоли: `Adventure.validateLevels()`.

## 3. Прогресс, жизни, бустеры

Всё хранится в `localStorage` под ключом `block-chpok-adventure-v1`. На Яндексе
`localStorage` подменён на safe storage SDK, поэтому прогресс автоматически уходит
в облако для авторизованных игроков — отдельной синхронизации не требуется.

```json
{
  "v": 1,
  "levels": { "1": { "stars": 3, "score": 960 } },
  "current": 5,
  "hearts": 4,
  "heartsAt": 1750000000000,
  "boosters": { "hammer": 1, "shuffle": 1 }
}
```

**Звёзды** считаются от неизрасходованных ходов, поэтому работают для любой цели и
не требуют настройки в данных уровня: 1 звезда — пройдено, 2 — осталось ≥20% ходов,
3 — ≥40%. Продолжение за rewarded ограничивает результат двумя звёздами, чтобы
остался смысл вернуться и закрыть уровень «чисто». Три звезды с первой попытки
дают +1 молоток.

**Жизни**: максимум 5, восстановление 1 за 12 минут, списывается одна при проигрыше.
Если игрок продолжил уровень за rewarded — жизнь возвращается (это не проигрыш).
На нуле жизней уровень не стартует: показывается экран с таймером, rewarded на
+2 жизни и предложением сыграть в классику (игрока не выгоняем из игры).

**Бустеры**: молоток (уничтожает содержимое любой клетки целиком, ход не тратит) и
перемешивание трея. Пустой бустер показывает «+» и предлагает получить его за рекламу.

## 4. Реклама

| Плейсмент | Момент | Тип |
|---|---|---|
| Продолжить уровень: +5 ходов | закончились ходы | rewarded |
| Новые фигуры | тупик (нет валидных ходов) | rewarded |
| Сбросить таймер бомбы | взрыв бомбы | rewarded |
| +2 жизни | закончились жизни | rewarded |
| +1 бустер | тап по пустому бустеру / экран победы | rewarded |
| Interstitial | переход на следующий уровень | interstitial |

Продолжение предлагается **один раз за попытку** (`run.usedContinue`) — иначе уровень
перестаёт быть уровнем. Interstitial между уровнями идёт через общий с классикой
шлюз `GameCore.maybeShowInterstitial`, поэтому лимиты частоты (каждая 3-я партия,
партия дольше 30 с, не чаще одного раза в 2 минуты, пропуск сразу после rewarded)
считаются в одном месте и режимы не могут перекрутить друг другу воронку.

## 5. Лидерборды

Фасад `window.GameLeaderboards` с двумя бордами:

| Ключ | Техническое имя | Что отправляем |
|---|---|---|
| `endless` | `blockChpock` | рекорд классики |
| `adventure` | `blockChpockAdventure` | сумма звёзд, в `extraData` — текущий уровень |

**Консоль разработчика Яндекс.Игр:** оба борда (`blockChpock`, `blockChpockAdventure`)
уже созданы. Имена в коде (`BOARDS` в `leaderboards.js`, `LEADERBOARD_NAME` в
`yandex-sdk.js`) должны совпадать с техническим названием борда символ в символ —
иначе `setScore` вернёт ошибку, а модалка покажет «лидерборды недоступны» (игра при
этом продолжает работать).

**jam-sdk**: методов лидерборда в контракте game-bridge пока нет, они обещаны в
ближайшем обновлении. Jam-адаптер определяется по набору кандидатов имён методов
(`JAM_SUBMIT_METHODS` / `JAM_FETCH_METHODS` в `leaderboards.js`): как только
jam-sdk отдаст любой из них, лидерборды поедут через портал без правок игрового
кода. Когда финальные имена станут известны — поправить только эти два массива.

Запись результата на Яндексе требует авторизации, чтение — нет. Если игрок не
авторизован, модалка показывает кнопку входа и после него сразу досылает результат.

## 6. Иконки (спрайты)

Все иконки интерфейса — обычные PNG из `src/assets/theme/icons/`. Сейчас там лежат
**плейсхолдеры** с подписями (`CR` = crate, `HM` = hammer и т.д.), сгенерированные
`node scripts/make-icon-placeholders.mjs`.

**Как заменить на финальный арт:** положить свой файл **с тем же именем** в
`src/assets/theme/icons/` и пересобрать (`npm run build`). CSS и код править не нужно —
имена и размеры уже зашиты. Размер файла — 3x от размера отрисовки (под retina);
формат PNG с альфа-каналом, квадрат, фон прозрачный, рисунок с небольшим внутренним
отступом (иконки масштабируются через `background-size: contain`).

Символ `★` остался текстом в двух местах, где он часть строки, а не иконка: подпись
кнопки «Приключение» на стартовом экране и результат в лидерборде приключения
(`★ 117 · Ур. 40`). Если нужен арт и там — эти строки собираются в
`refreshSplashSubtitles` (`game.js`) и `formatScore` (`leaderboards.js`).

Препятствия на доске (камень, ящик, лёд, бомба, самоцвет, дыра) — **не спрайты**, они
нарисованы CSS-градиентами в `styles.css` (блок «1. Препятствия»), потому что должны
работать поверх WebGL-канваса в обоих режимах рендера. Если для них тоже нужен арт,
это отдельная задача: понадобятся текстуры и в Pixi-рендере.

**Добавление новой иконки** (например, под новый тип цели): дописать запись в массив
`ICONS` в `scripts/make-icon-placeholders.mjs` и запустить его. Скрипт перезаписывает
файлы, поэтому уже нарисованный арт из массива лучше удалить.

## 7. Ручной чек-лист

* Стартовый экран: две кнопки режимов, подписи с рекордом и прогрессом.
* Карта: главы, звёзды, замки, автоскролл к текущему уровню, таймер жизней.
* Карта: фон меняется кроссфейдом при прокрутке между главами, без «пустых» кадров.
* Уровень: HUD (номер, ходы, чипы целей), баннер целей на старте.
* Препятствия видны в обоих рендерах (`?renderer=dom` и `?renderer=pixi`).
* Бомба тикает ровно раз за ход; очистка линии сквозь бомбу обезвреживает её.
* Молоток: тап по клетке уничтожает содержимое, ход не тратится, счётчик убывает.
* Победа: звёзды, счёт, «Дальше» / «+1 молоток за рекламу» / «Карта».
* Провал по ходам / тупик / бомба — свой rewarded-CTA у каждого случая.
* Ноль жизней: таймер, rewarded, выход в классику.
* «В меню» в настройках возвращает выбор режима с чистой доской.
* Классика после приключения работает как раньше (рекорд, второй шанс, interstitial).

## 8. Фоны глав на карте

У каждой главы свой фон карты — поле `bg` в `ADVENTURE_CHAPTERS`, путь относительно
корня сборки. Файлы лежат в `src/assets/maps/`, формат JPG 748×1024 (портрет,
`background-size: cover`), вес ~130–220 КБ.

| Глава | Файл | Что нарисовано |
|---|---|---|
| 1. Тёплая кухня | `cozy_kitchen.jpg` | кухня с печью |
| 2. Уютная кладовая | `evening_parlor.jpg` | кладовая с банками и крупами |
| 3. Вечерняя гостиная | `snug_pantry.jpg` | гостиная с камином |
| 4. Домик на ветке | `branch_hidaway.jpg` | домик на дереве |

Имена файлов глав 2 и 3 перепутаны в исходном арте — `bg` сопоставлен по содержимому
картинки, а не по имени. Если файлы переименуют, надо поправить `bg` в `levels.js`.

**Как это работает.** В `.adv-map` живёт `.adv-map-bg` с двумя слоями
`.adv-map-bg-layer` и скримом `.adv-map-bg-scrim` поверх них (скрим держит контраст
узлов и плашек — без него светлый арт съедает UI). При прокрутке `.adv-map-scroll`
`adventure.js` считает, чья глава пересекает опорную линию на 35% высоты окна
(`chapterInView`), и вызывает `setMapBackground`: входящий слой получает картинку,
z-index выше уходящего и класс `is-visible`, уходящий его теряет — CSS-переход
`opacity 0.55s` даёт кроссфейд. Роли слоёв чередуются, поэтому смена главы посреди
перехода не даёт рывка: opacity доезжает с текущего значения. Все фоны прогреваются
через `new Image()` при первой сборке карты, иначе первый показ мигает пустотой.

Замена арта: положить файл с тем же именем в `src/assets/maps/` и пересобрать. Новая
глава — добавить файл и прописать `bg`; код и CSS править не нужно.
